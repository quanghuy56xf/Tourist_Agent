HERA: Userflow hiện tại

Đối chiếu trực tiếp từ frontend, backend và luồng RAG trong codebase ngày 15/06/2026.

Thao tác người dùng Điểm lựa chọn Xử lý hệ thống Kết quả Điểm lỗi/rủi ro

1. Khách tham quan

Mở HERA

Chọn ngôn ngữ và nhóm trải nghiệm.

→

Chọn cách khám phá

Camera, tải ảnh hoặc tour.

→

Nhận diện hiện vật

Nén ảnh → API search → xếp hạng kết quả.

→

Xem nội dung

Ảnh, câu chuyện theo persona/ngôn ngữ, âm thanh.

→

Tương tác tiếp

Hỏi đáp AI, quét hiện vật khác hoặc tiếp tục tour.

Camera

Chụp → tìm kết quả → tự mở hiện vật tốt nhất; kết quả yếu thì cho khách chọn.

Tải ảnh

Chọn ảnh có sẵn → cùng pipeline nhận diện → trang chi tiết hiện vật.

Tour

Chọn tour → xem các điểm → quét đúng hiện vật theo thứ tự → hoàn thành tour.

2. Ban quản trị

Đăng nhập

Admin hoặc manager; manager bị giới hạn theo khu.

→

Chọn khu di tích

Ngữ cảnh dùng chung cho tài liệu và hiện vật.

→

Quản lý nội dung

Tài liệu RAG, hiện vật, tour, tài khoản.

→

Backend xử lý

Lưu DB/file, embedding, Chroma + BM25, sinh lại nội dung liên quan.

→

Xuất bản cho khách

Nhận diện, thuyết minh, chat và tour dùng dữ liệu mới.

Admin

Tạo khu, tạo/vô hiệu hóa manager, gán quyền theo khu.

Tài liệu RAG

Chọn khu → nhập text hoặc upload TXT/DOCX/PDF → parse → chunk → index → cập nhật item liên quan.

Hiện vật & tour

Đăng ký ảnh nhiều góc, mô tả, gán khu; sau đó tạo tour và sắp xếp điểm dừng.

Điểm lỗi upload RAG

Admin đã đăng nhập

Token nằm trong sessionStorage.

→

Upload bằng XHR

Request không gắn header Authorization.

→

Backend từ chối

Khi bật auth: trả 401 trước khi đọc/parse file.

→

UI báo lỗi chung

Người dùng dễ hiểu nhầm là RAG/PDF bị lỗi.

Đánh giá và ưu tiên cải tiến

P0

Sửa xác thực upload

Gắn Bearer token cho XHR và thêm test đảm bảo request upload có token khi admin đã đăng nhập.

P0

Phân biệt các loại lỗi

Hiển thị rõ 401/403, PDF scan không có text, RAG unavailable, lỗi mạng và lỗi quá dung lượng.

P1

Trạng thái ingest thực

Hiện UI đang gọi “uploading/encoding” nhưng backend xử lý đồng bộ. Nên có trạng thái queued, parsing, indexing, ready/failed và retry.

P1

Giới hạn và OCR

Cấu hình hiện cho phép 0 = không giới hạn. Nên đặt giới hạn file/chunk và hướng dẫn OCR khi PDF chỉ chứa ảnh.

P1

Tour phải theo khu đang chọn

Trang tạo tour đang lấy toàn bộ hiện vật, dễ tạo tour trộn nhiều khu. Nên lọc theo active group.

ĐIỂM TỐT

Phân quyền theo khu đã có nền tảng

Admin/manager, active group và kiểm tra quyền backend đã được tách khá rõ; chỉ còn một số request chưa dùng thống nhất helper xác thực.
